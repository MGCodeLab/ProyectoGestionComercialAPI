## 🎯 Por qué

### Problema previo:
1. **Sin filtro automático:** Queries a `dbContext.Productos.ToListAsync()` devolvían TODOS los productos, incluyendo los inactivos (Activo=false)
2. **Inconsistencia en negocio:** Múltiples lugares del código tenían que hacer `.Where(p => p.Activo)` manualmente
3. **Olvidos fáciles:** Desarrolladores podían olvidar agregar el filtro, exponiendo datos eliminados
4. **Código repetitivo:** DRY violado en cada query a través de la aplicación

### Solución:
- **Global Query Filter:** EF Core `HasQueryFilter()` aplicado automáticamente a TODAS las queries de AuditableEntity
- **Centralizado:** Un solo lugar en AppDbContext
- **Escalable:** Nuevas entidades automáticamente incluidas en el filter
- **Bypasseable:** Métodos de extensión para casos especiales (admin, reportes)

---

## ✅ Implementación Técnica

### 1. Global Soft Delete Filter en AppDbContext

```csharp
private static void ApplySoftDeleteFilters(ModelBuilder modelBuilder)
{
    // Reflejo a través de todas las entidades
    foreach (var entity in modelBuilder.Model.GetEntityTypes())
    {
        // Si es AuditableEntity, aplica filter
        if (typeof(AuditableEntity).IsAssignableFrom(entity.ClrType))
        {
            // Construye expresión: e => e.Activo == true
            var parameter = Expression.Parameter(entity.ClrType, "e");
            var property = Expression.Property(parameter, "Activo");
            var constant = Expression.Constant(true);
            var equalExpression = Expression.Equal(property, constant);
            var lambda = Expression.Lambda(equalExpression, parameter);

            // Aplica el filter globalmente
            entity.SetQueryFilter(lambda);
        }
    }
}
```

### 2. Extensiones para Casos Especiales

```csharp
// Incluir registros soft-deleted (admin, auditoría)
var allProductos = await context.Productos
    .IncludeSoftDeleted()  // Ignora el global filter
    .ToListAsync();

// Solo registros eliminados
var deletedProductos = await context.Productos
    .OnlySoftDeleted()  // Filter: Activo=false
    .ToListAsync();

// Verificar si un registro está eliminado
if (producto.IsSoftDeleted())
{
    // ...
}
```

## 🚨 Consideraciones & Gotchas

### 1. Performance de Reflection
Cada AppDbContext instanciación itera sobre tipos. Esto es **negligible** ya que OnModelCreating se ejecuta una sola vez (cached).

### 2. Bypass en Tests
Si en tests necesitas tanto activos como deletedos:
```csharp
var all = context.Productos.IncludeSoftDeleted().ToListAsync();
```

### 3. Queries Complejas
Si tienes LINQ complejos con múltiples .Include(), el filter se aplica al final. **Behavior es el esperado.**

### 4. Raw SQL
Si usas `context.Database.SqlQuery()` directamente, el filter NO aplica (es raw SQL). **Usa DbContext queries en lugar de raw SQL cuando sea posible.**

## 🎓 Patrón: Global Query Filter en EF Core

Este es un patrón estándar para implementar soft deletes a nivel framework:

```csharp
// Reflejo dinámico
foreach (var entityType in modelBuilder.Model.GetEntityTypes())
{
    if (typeof(ISoftDeletable).IsAssignableFrom(entityType.ClrType))
    {
        // Construye y aplica filter expresión
        var parameter = Expression.Parameter(entityType.ClrType);
        var property = Expression.Property(parameter, nameof(ISoftDeletable.IsDeleted));
        var lambda = Expression.Lambda(Expression.Equal(property, Expression.Constant(false)), parameter);
        entityType.SetQueryFilter(lambda);
    }
}
```
